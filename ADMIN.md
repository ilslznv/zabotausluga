# Администрирование сайта

Админка работает вместе с сервером Node.js в папке `WEB2`. Она сохраняет изменения на сервере. Открытие HTML-файла двойным щелчком подходит для просмотра сайта, но для входа и редактирования нужен запущенный сервер.

Нужен Node.js 22 или новее. Внешние зависимости устанавливать не требуется. Все команды ниже выполняются из папки `WEB2`.

## Первый запуск на компьютере

```sh
npm run build
npm start
```

Откройте `http://127.0.0.1:4174/admin/login.html`. Пока аккаунт не создан, локально доступна форма создания администратора. Выберите логин и пароль длиной от 12 до 256 символов. Используйте отдельный пароль, который не применяется в других сервисах.

Логин может содержать от 3 до 64 букв, цифр, точек, дефисов и подчёркиваний. После создания аккаунта форма регистрации отключается. Доступен один аккаунт администратора.

Создать аккаунт можно и через терминал:

```sh
npm run admin:create -- --username admin
```

Пароль и его подтверждение вводятся скрыто. Пароль не записывается в исходники и не выводится в консоль; на диске хранится его хеш с индивидуальной солью.

## Размещение на хостинге

Загрузите папку `WEB2` целиком, включая `tools`, исходные данные и `dist`. Настройте запуск приложения командой `npm start`. Рабочая папка приложения должна быть `WEB2`.

Установите переменные окружения:

| Переменная | Значение |
| --- | --- |
| `HOST` | `0.0.0.0`, если этого требует хостинг |
| `PORT` | Порт, назначенный хостингом; локально по умолчанию `4174` |
| `ADMIN_PUBLIC_ORIGIN` | Полный адрес сайта, например `https://example.ru`, без пути, параметров и фрагмента |

На публичном сервере аккаунт создаётся через `npm run admin:create -- --username admin`. Через страницу входа создать первый аккаунт на публичном домене нельзя. Это исключает регистрацию посторонним посетителем до владельца сайта.

Если хостинг запускает команды без интерактивного терминала, временно задайте пароль в защищённой переменной окружения `ADMIN_PASSWORD`, затем выполните команду создания аккаунта. После успешного создания удалите эту переменную из настроек хостинга. Передавать пароль аргументом команды не нужно.

Включите HTTPS на домене. Если перед Node.js стоит прокси, он должен передавать исходный заголовок `Host`: адрес должен совпадать с `ADMIN_PUBLIC_ORIGIN`. Заголовкам `X-Forwarded-Proto` и `X-Forwarded-Host` приложение для проверки входа не доверяет. При `ADMIN_PUBLIC_ORIGIN=https://…` cookie сессии получает флаг `Secure` и передаётся браузером только по HTTPS.

Адрес входа: `https://example.ru/admin/login.html`.

## Данные и обновление приложения

Не размещайте приватные файлы админки внутри `dist`: сервер публикует только файлы из `dist`.

| Путь по умолчанию | Что хранится |
| --- | --- |
| `.admin/users.json` | Логин, соль и хеш пароля |
| `cms-content.json` | Сохранённый контент сайта и правки |
| `.admin/backups/` | История версий контента для восстановления |
| `dist/assets/uploads/` | Документы и изображения, загруженные через админку |
| `content.json`, `dist/assets/documents/`, `dist/assets/images/` | Исходные материалы сайта |

При следующем деплое обязательно сохраните `cms-content.json`, `.admin` и `dist/assets/uploads`. Замена папки новым архивом без этих данных потеряет изменения или доступ к аккаунту. Не очищайте папку загрузок: предыдущие версии контента могут ссылаться на её файлы.

На хостинге с временной файловой системой нужен постоянный диск. Приватные данные можно вынести на него переменными окружения:

| Переменная | Пример абсолютного пути |
| --- | --- |
| `ADMIN_STATE_DIR` | `/var/lib/zabota/admin` |
| `CMS_STATE_FILE` | `/var/lib/zabota/cms-content.json` |
| `CMS_BACKUP_DIR` | `/var/lib/zabota/backups` |

Папку постоянного диска с загрузками подключите к `WEB2/dist/assets/uploads`, например через подключение каталога в панели хостинга или bind mount. Она должна быть доступна серверу для записи. Если хостинг не поддерживает подключение каталога, сохраняйте эту папку перед заменой приложения и возвращайте её после деплоя.

Для проекта используйте один экземпляр процесса Node.js. Сессии находятся в памяти процесса; режим cluster и несколько серверных реплик потребуют общего хранилища сессий и согласованной записи контента. Перезапуск сервера завершает текущие сессии, после него нужно войти снова.

## Работа с контентом и файлами

Войдите, откройте нужную страницу или раздел, внесите изменения и проверьте предварительный просмотр. Сохранение применяется к публичному сайту. Перед крупной заменой материалов полезно сделать отдельную резервную копию.

Для загрузки доступны изображения PNG, JPG, WebP, GIF и документы PDF, DOCX, RTF, TXT. Максимальный размер одного файла — 25 МБ. Сервер проверяет расширение, MIME-тип и сигнатуру файла; SVG, HTML, исполняемые файлы и ZIP-архивы не принимаются. DOCX дополнительно проверяется как документ Word. Текстовые TXT-файлы должны быть в UTF-8.

Загрузки получают случайные имена и сохраняются только в `dist/assets/uploads`. Изменение контента не удаляет исходные документы.

## Резервные копии и восстановление

История в админке помогает вернуть предыдущий контент, но не заменяет независимые резервные копии сервера. Сохраняйте вместе:

- текущий файл `cms-content.json` или файл из `CMS_STATE_FILE`;
- папку `.admin` или каталоги из `ADMIN_STATE_DIR` и `CMS_BACKUP_DIR`;
- все загруженные файлы из `dist/assets/uploads`;
- исходники приложения и исходные изображения и документы.

Храните копию отдельно от рабочего хостинга, ограничьте к ней доступ. Аккаунт и резервные копии могут содержать приватные служебные данные. Для согласованной копии на короткое время остановите приложение или воспользуйтесь снимком диска хостинга.

Для полного восстановления остановите приложение, верните эти файлы и каталоги, проверьте права записи, соберите страницы командой `npm run build` и запустите `npm start`. Для возврата только контента воспользуйтесь историей версий в админке. После восстановления проверьте главную страницу и ссылки на загруженные документы.

## Смена пароля

Если пароль забыт или его нужно заменить, используйте терминал хостинга:

```sh
npm run admin:create -- --username admin --replace
```

Введите новый пароль скрыто или временно используйте `ADMIN_PASSWORD`, как при первом создании. Смена пароля отзывает прежние сессии. Логин в команде можно изменить одновременно с паролем. Автоматического восстановления по электронной почте нет.

Сессия действует до восьми часов. Завершайте работу кнопкой выхода, особенно на общем компьютере.

## API для сопровождения

Все пути начинаются с `/api/admin`. Ответы JSON не кешируются. Ошибки возвращаются как `{ "error": "понятное сообщение" }` без трассировки сервера.

| Метод и путь | Назначение |
| --- | --- |
| `GET /session` | Состояние входа, возможность первого локального создания и CSRF-токен для вошедшего пользователя |
| `POST /setup` | Первый локальный аккаунт: `{username,password}` |
| `POST /login` | Вход: `{username,password}` |
| `POST /logout` | Выход |
| `GET /content` | Текущий контент, версия и сведения для редактора |
| `PUT /content` | Сохранение данных редактора; конфликт версии требует повторно загрузить актуальные данные |
| `POST /preview` | HTML для предварительного просмотра: `{page,content}` |
| `POST /upload` | Бинарное тело файла, заголовки `Content-Type` и `X-File-Name` с именем через `encodeURIComponent` |
| `GET /versions` | Список сохранённых версий |
| `POST /restore` | Восстановление версии: `{id}` |

Для действий после входа необходима серверная cookie. Все изменяющие запросы требуют заголовок `X-CSRF-Token` со значением из ответа входа или `GET /session`. Запросы с чужим `Origin` отклоняются. Загрузка возвращает `{src,filename,size,format}`, где `src` — относительный путь `assets/uploads/…`.

После восьми неудачных попыток входа с одного IP следующие попытки ограничиваются на десять минут. Смена пароля и перезапуск процесса отзывают сессии. Многофакторная авторизация, роли редакторов и общий сервер сессий в этой версии не предусмотрены.

Проверка API:

```sh
node --test tools/admin-api.test.mjs
```

Тесты используют временные каталоги и не меняют аккаунт или контент рабочего сайта.
