# Отправка обращений на почту

Форма «Написать нам» отправляет обращение с сервера Node.js на `zabota-usluga72@mail.ru`. Почтовое приложение посетителя не требуется. Онлайн-опрос работает отдельно: ответы сохраняются на сервере, а на сайте публикуются общие результаты без свободных комментариев.

Настройте SMTP в переменных окружения приложения на хостинге. Пароль не добавляется в HTML, JavaScript, исходники или контент админки.

## Подключение Mail.ru

1. Владелец входит в свой ящик Mail.ru. Для создания пароля приложения к ящику должен быть привязан телефон.
2. В настройках безопасности откройте «Пароли для внешних приложений», создайте отдельный пароль с названием, например «Сайт Заботливая услуга». Выберите разрешение «Только отправка писем в Почте».
3. Скопируйте созданный пароль в защищённую переменную `SMTP_PASSWORD` в панели хостинга. Основной пароль ящика для подключения не подходит.

Параметры Mail.ru: сервер `smtp.mail.ru`, порт `465`, шифрование SSL/TLS. Инструкция проверена по [официальной справке Mail.ru](https://help.mail.ru/mail/login/mailer/) 3 октября 2026 года.

## Переменные окружения

| Переменная | Значение для этого сайта |
| --- | --- |
| `SMTP_HOST` | `smtp.mail.ru` |
| `SMTP_PORT` | `465` |
| `SMTP_SECURE` | `true` — TLS с начала соединения |
| `SMTP_USER` | `zabota-usluga72@mail.ru` — полный адрес ящика отправителя |
| `SMTP_PASSWORD` | Отдельный пароль приложения, созданный владельцем в Mail.ru |
| `SMTP_FROM` | `zabota-usluga72@mail.ru` |
| `MAIL_TO` | `zabota-usluga72@mail.ru` — получатель обращений |
| `ADMIN_PUBLIC_ORIGIN` | Полный адрес сайта, например `https://example.ru`, без пути и параметров |

`SMTP_USER` и `SMTP_PASSWORD` обязательны. По умолчанию используются сервер Mail.ru, порт `465` и TLS; `SMTP_FROM` берётся из `SMTP_USER`, а `MAIL_TO` — `zabota-usluga72@mail.ru`. Для ясности лучше задать значения в панели явно. Если отправителем будет другой ящик, измените `SMTP_USER` и `SMTP_FROM` вместе.

`MAIL_TO` — серверная настройка. Изменение адреса в разделе контактов админки меняет опубликованный адрес, но не перенаправляет поступающие обращения.

После изменения переменных перезапустите приложение командой `npm start` или кнопкой перезапуска в панели хостинга. Разрешите исходящие соединения приложения к `smtp.mail.ru:465`. Приложение проверяет сертификат SMTP-сервера; отключать проверку TLS не требуется. Для другого провайдера режим `SMTP_SECURE=false` использует обязательный STARTTLS — это не режим отправки без шифрования.

Пароль задаёт сам владелец в панели хостинга. Передавать его в переписке или сохранять в папке `dist` не нужно. Если пароль приложения заменён в Mail.ru, обновите `SMTP_PASSWORD` и перезапустите Node.js.

## Проверка

1. Откройте сайт по его публичному HTTPS-адресу и отправьте через форму одно тестовое обращение без персональных данных, например сообщение «Проверка отправки с сайта».
2. Убедитесь, что форма показывает успешный результат. Он появляется после подтверждения SMTP-сервером приёма письма.
3. Откройте ящик получателя и проверьте входящие письма и папку спама. Прочитайте тестовое обращение: это подтверждает доставку до ящика.

Без настроенных SMTP-данных сервер возвращает ошибку `503`, а форма сообщает, что отправка недоступна. Успешная отправка не имитируется; введённый текст сохраняется в форме, чтобы посетитель мог повторить попытку.

При ошибке авторизации проверьте полный адрес `SMTP_USER`, отдельный пароль приложения и доступ внешних сервисов к SMTP в настройках безопасности Mail.ru. [Официальная справка по настройкам безопасности](https://help.mail.ru/mail/security/protection/settings/).

Сервер ограничивает отправку пятью попытками за десять минут с одного адреса соединения и четырьмя одновременными отправками. Если хостинг использует обратный прокси, адрес соединения может быть общим для посетителей. При размещении проверьте это ограничение вместе с настройками прокси; заголовок `X-Forwarded-For` приложение не принимает за достоверный адрес посетителя.

Автоматический тест протокола запускается так:

```sh
node --test tools/mail-api.test.mjs
```

Он использует тестовый SMTP-сервер и не отправляет настоящие письма. Проверка доставки через Mail.ru выполняется владельцем после настройки на хостинге.
